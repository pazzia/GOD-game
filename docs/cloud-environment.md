# Облачная среда разработки

Рабочий каталог — `/workspace/GOD-game`. Используйте существующий checkout;
отдельный worktree не нужен. Состояние поставки и ссылка на последний проверенный
APK находятся в `docs/reviews/ci/android-preview.json`.

Для этой версии закреплён Godot **4.7.2**. Системный Godot 4.6.3 не используйте.
Установленный бинарный файл проверен по `tools/godot-4.7.2.SHA512-SUMS.txt`.
В среде также доступны Python 3.12, Pillow 12.3.0, NumPy 2.3.5 и FFmpeg.

```bash
cd /workspace/GOD-game
export GODOT_BIN=/workspace/setup-tools/Godot_v4.7.2-stable_linux.x86_64
export XDG_CONFIG_HOME=/workspace/setup-tools/config
export XDG_CACHE_HOME=/workspace/setup-tools/cache
export XDG_DATA_HOME=/workspace/setup-tools/data
mkdir -p "$XDG_CONFIG_HOME" "$XDG_CACHE_HOME" "$XDG_DATA_HOME"
"$GODOT_BIN" --headless --editor --path . --import --quit
```

После импорта проверяйте журнал на ошибки движка: одного кода завершения
недостаточно. Постоянный сервер не требуется. Для GUI нужен дисплей; реальные
снимки интерфейса получает `tools/capture_ui.py` через Xvfb/Mesa.

Полный прогон:

```bash
python3 tools/verify_project.py --godot "$GODOT_BIN" --ui --audio
```

Команда обновляет отчёты в `tests/reports/`. Для независимого воспроизведения
используйте временную копию исходников без `.git`, `.godot` и `__pycache__`, сначала
выполните импорт. Актуальный результат содержит 31 набор проверок, ноль ошибок
движка и неизменный отпечаток runtime. Исторический отчёт не подтверждает новые
изменения. Принудительный `--quit-after` обходит ожидаемое завершение аудио;
штатное закрытие проверяют существующие shutdown/drain-тесты.

APK собирается и публикуется GitHub Actions из нового тега `android-preview-*`.
Workflow закрепляет инструменты, прогоняет проверки, сверяет ресурсы, подпись,
Android manifest и отпечаток исходников. Godot `SCREEN_SENSOR_LANDSCAPE=4` в
версии 4.7.2 соответствует Android `userLandscape=11`. После успешной сборки APK,
отчёты и контрольные суммы доступны в GitHub Releases. Ключ подписи временный,
не публикуется и не хранится в репозитории.

Для Git используется штатная HTTPS-аутентификация среды. Запрет доступа к
`api.github.com` не означает отсутствие Git-доступа и не требует нового токена.
Разрешение API сохранено в черновике конфигурации; до применения черновика статус
сборок можно читать на публичных страницах Actions, файлы скачивать из Releases.

Настройки установки и запуска сохранены также в черновике облачной среды.
Сохранение черновика само по себе не публикует снимок среды: для будущих задач
нужно сохранить изменения в настройках среды и опубликовать её.
