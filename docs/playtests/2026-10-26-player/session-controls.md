# Управление нативной сессией Игрока

Рабочая папка: `/workspace/GOD-game`.
Сессия: `build/player-session/session.json`, Xvfb display 103, **844×390**.
Игра запущена обычным `main.tscn`, с новым изолированным профилем.
Код игры, команды ядра, готовые решения и подмена сохранения не используются.

Каждое действие выполняется реальным событием XTest в нативном окне Godot.
Затем сохраняются сырой снимок X11 и запись в
`docs/playtests/2026-10-26-player/session/events.jsonl`.
Координаты — пиксели снимка, начало в левом верхнем углу.

```bash
python3 tools/player_session.py status
python3 tools/player_session.py --note 'Моё намерение перед действием' click 100 200
python3 tools/player_session.py --note 'Следующее действие' key Escape
python3 tools/player_session.py --note 'Прокрутить видимый список' scroll down 3 --x 600 --y 240
python3 tools/player_session.py --note 'Перетащить видимый элемент' drag 100 200 300 220
python3 tools/player_session.py --wait 2 --note 'Дождаться реакции' capture
python3 tools/player_session.py --note 'Проверить продолжение после перезапуска' restart
```

Опции `--note`, `--wait`, `--session-dir` ставятся **до** названия действия.
`--wait` по умолчанию 0.7 секунды; разрешено 0–10 секунд.
Поддерживаются X11-клавиши `Escape`, `Return`, `Tab`, `space`, стрелки
`Up`/`Down`/`Left`/`Right` и сочетания вроде `ctrl+s`.

После команды откройте указанный PNG через `view_image` и принимайте решение
по экрану. Записывайте собственное ожидание и наблюдение, не только координаты.
Не запускайте несколько команд ввода одновременно.

`restart` завершает desktop-процесс Godot через SIGTERM и повторно запускает
его с тем же изолированным профилем; это не проверка Android lifecycle.
`stop` завершает только
процессы этой сессии и сохраняет профиль. Новый `start` создаёт новый профиль,
не удаляя старые. Менеджер уже подготовил чистый запуск; повторный `start`
для первого прохода не требуется.

Это **desktop mouse/keyboard AI-прогон**, не физический Android и не touch.
Аудиодрайвер `Dummy`: субъективное прослушивание не выполняется.
Снимки — нативные, без ретуши/масштабирования. Число секунд между командами
не считается временем размышления человека или показателем производительности телефона.

## Защита повторных запусков

После исходного игрового прогона в инструмент добавлены две инфраструктурные
защиты. Они **не использовались во время исходных 117 событий Игрока** и не
меняют сохранённые journal/PNG/manifest этого прогона.

Новый `start` требует пустой `--evidence-dir`: существующие кадры, журнал и
manifest не перезаписываются. Для следующего прогона укажите новую папку.
`stop`/`restart` сверяют записанные PID, время старта процесса, boot ID,
SHA-256 полной командной строки. Сигнал отправляется через Linux
pidfd, поэтому переиспользование PID не направит его другому процессу.
При несовпадении или отсутствии identity живого процесса команда отказывает,
не посылая ему сигнал. Старые живые сессии без identity автоматически не мигрируют.
