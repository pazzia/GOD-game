ВЕРДИКТ
Материалы существующей Android debug-версии 0.2.0 build 3 в наличии.
Повреждённых или потерянных обязательных runtime-ресурсов не найдено.

Полный релиз по ТЗ и автоматический деплой пока не готовы.

3. НОВЫЙ ПОЛНЫЙ ПРОГОН
Команда:
python3 tools/verify_project.py --godot /absolute/path/to/Godot_v4.7.2-stable_linux.x86_64 --ui
Итог: 24 из 25 наборов прошли, общий status=failed.
Runtime-файлы во время прогона не менялись. Кампания: 732 checks, 0 failures.
Компоновка: 5436 checks, 0 failures. Сложные UI journeys: 59 checks, 0 failures.

Неуспешен test_service_boundaries.gd. Его 28 функциональных проверок проходят,
процесс возвращает 0, но движок при завершении периодически сообщает:
WARNING: 22 ObjectDB instances were leaked at exit
ERROR: 5 resources still in use at exit
Обёртка verify_project.py правильно считает такой запуск неуспешным.
Отдельный verbose-перезапуск прошёл. В трёх дополнительных изолированных
обычных запусках результат повторился один раз: [{"attempt": 1, "process_exit_code": 0, "errors": [], "passed": true}, {"attempt": 2, "process_exit_code": 0, "errors": ["WARNING: 22 ObjectDB instances were leaked at exit (run with `--verbose` for details).", "ERROR: 5 resources still in use at exit (run with --verbose for details)."], "passed": false}, {"attempt": 3, "process_exit_code": 0, "errors": [], "passed": true}]
Это воспроизводимая нестабильность завершения приёмочного теста. Пока не
установлено, удерживает ссылки сам тест, сервис или код движка. Нельзя
объявлять её исправленной либо связывать с прошлыми сбросами сеанса ChatGPT.

4. ЧТО ЕЩЁ НЕ ПРОИЗВЕДЕНО ДЛЯ ПОЛНОГО РЕЛИЗА
В реестре 78 planned_not_produced: 47 специальных анимаций, 30 scene_overlay
и один предмет PROP_POSTER. У всех 78 actual_files пуст, плановые файлы не найдены.
Кроме этого, отдельно остаются направления моделей, полные актёрские циклы,
интеграция части персонажей/реквизита, полная постановка сцен и слушательская
приёмка. Наличие базовых ресурсов не закрывает эти частичные позиции.
Полный перечень отсутствующих позиций приведён ниже.

5. ГОТОВНОСТЬ ПЕРЕДАЧИ В GITHUB
https://github.com/pazzia/GOD-game на момент проверки содержит только .gitignore.
В исходном архиве workflow .github/workflows отсутствует; автоматическая
сборка и публикация APK не настроены. Исходники надо передавать распакованными,
APK — отдельным артефактом/релизом. В распакованном проекте нет файлов больше
100 MiB; наибольшие отдельные файлы — несколько MiB. Движок и инструменты
в исходный архив намеренно не входят: присутствуют bootstrap_native.py,
native_packages.lock.json и контрольные суммы Godot. Android export templates
и signing subset надо восстановить в CI; желательно кешировать загрузки.
Сохранённый тестовый ключ соответствует APK; выпускного магазинного ключа нет.

6. ГРАНИЦЫ ЭТОЙ ПРОВЕРКИ
Новая сборка APK из исходников в этом проходе не выполнялась: проверялся
сохранённый APK, его точное соответствие runtime-исходникам, подпись и ресурсы.
Не выполнялись установка на физический Android, FPS/память/нагрев, iOS,
покупки, субъективная художественная/звуковая приёмка и тест с новыми игроками.
Исходный архив и production-код не изменялись; GitHub в этом проходе не изменялся.

7. БЭКЛОГ ПРОВЕРКИ
PRE-01 / P0 для CI / открыто: нестабильное завершение test_service_boundaries.gd.
Воспроизведение: новый изолированный XDG_DATA_HOME, headless Godot 4.7.2,
запуск теста несколько раз; возможны 22 leaked instances и 5 ресурсов.
Последствие: полный приёмочный runner падает, даже когда 28 assertions прошли.
Причина отсрочки: текущий проход — аудит готовности, причина удержания ссылок
ещё не локализована. Следующий шаг: определить владельцев объектов/ресурсов,
исправить освобождение и повторить проблемный набор и полный прогон.

PRE-02 / P0 для автоматического деплоя / открыто: исходники отсутствуют в main,
Godot CI и публикация APK не настроены. Следующий шаг: подготовить коммит,
закреплённый toolchain и workflow с проверками, подписью и публикацией; принять
результат по реальному успешному запуску и наличию установочного файла.

PRE-03 / P1 полного релиза / открыто: 78 непроизведённых позиций и частичная
художественная интеграция. Уже связаны с B07/B08/B09 и матрицей ресурсов.
Следующий шаг: производство/интеграция по IDs ниже и новая приёмка.

PRE-04 / P1 платформенной приёмки / не проведено: физический Android и iOS.
Связано с B11/B12. Нужны реальные устройства/среда; автоматические проверки
не засчитываются вместо установки и измерений.
