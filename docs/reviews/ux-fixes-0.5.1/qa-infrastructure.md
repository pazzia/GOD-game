# Технические события QA-сессии

Ранний `qa-session/` содержит только boot/start, выполненный до согласованного
общего editor-import. Он был остановлен до любых игровых действий и не входит
в доказательства повторного прохождения.

После import создана новая сессия display106,844×390 в `qa-session-final/`.
Игра дошла до настоящего меню, однако защита утилиты отклонила первую попытку
нажатия: первоначальный fingerprint командной строки был SHA-256 пустой строки.
Сравнение показало одинаковые PID/starttime/boot ID, а текущие argv Godot точно
совпадали с записанной командой запуска. Это гонка чтения `/proc/PID/cmdline`
при старте тестовой утилиты, не проблема игрового UX. Отказ произошёл до ввода.
Ни identity-проверки, ни сигнализация процессам не обходились молча.

Менеджер разрешил узкое исправление: `launch_identity` ограниченно ждёт непустые
argv, точно равные записанной команде запуска, сохраняя прежние PID/starttime/boot.
Три проверки прошли: переход от пустого fingerprint к actual argv, отказ на
неверные argv и отказ на другое время рождения процесса. Guard/pidfd не ослаблены.
По отдельному разрешению исправлен только fingerprint неиспользованной106-сессии
после сверки argv и birth identity, чтобы безопасно остановить её;
[запись ремонта](qa-identity-repair.json). Создан новый чистый профиль и каталог
`qa-session-reviewed/`, без повторного использования игровых действий.
Финальный observer-проход выполнен отдельно в `qa-observer-final/`.
