# Stage: выбор, размещение и читаемость связей

Реализованы stage-части PLR-002/004 и дополнительная находка скрытой диагностики.
Файлы: `presentation/stage_view.gd`, `tests/test_stage_targets.gd`,
`tests/test_stage_input_edges.gd`. Ядро, данные уровней и физическая геометрия
не изменялись этой ролью.

- Явный `placement_entity` отделён от обычного выбора. Только в режиме размещения
  совместимые места получают приоритет. Неподходящее нажатие выдаёт
  `target_tapped("placement_invalid", current_entity)`, не выбирает соседний
  предмет и не завершает режим. UI показывает причину и даёт отмену.
- Маркеры рисуются после фигур, с тем же логическим центром и минимумом144×144.
  Даже занятое рисунком совместимое место видно; обычный осмотр не становится
  скрытым режимом перемещения. Цели определяются по текущему mode, а не по
  устаревшему кадру hit-списка.
- Выбор предпочитает настоящую непрозрачную часть рисунка или видимую линию
  верёвки перед невидимой увеличенной областью соседнего предмета. При настоящем
  пересечении рисунков используется ближайший якорь; полный минимум касания
  и прежняя проверка отмены/перемещения пальца сохранены.
- Выбранный предмет имеет контур и читаемое имя ниже фактической границы HUD.
  Используются те же level-prefixed имена, что и в меню. У выбранного камня
  реальная вместимость объединяется с именем, без второй наложенной плашки.
- Груз L02 косметически сдвинут влево от профессора на215 native px, вниз18;
  смещение убывает по мере ухода с первоначальной точки. Положение в kernel,
  маршруты, опоры и лучи остаются прежними.
- Швартовочная верёвка рисуется поверх реквизита, концы заметны после крепления.
  Это существующая действительная связь, а не декоративное подтверждение.
  Старый клик Игрока около313,281 может по-прежнему выбирать верёвку: теперь
  именно там видна её линия. Центр видимого корпуса выбирает лодку.
- Удалена fixed-position текстовая строка обзора из мира. Реальные лучи
  остались в сцене; UI выводит числовой результат в измеряемой панели подсказки.
  Инспектор с несколькими заданными ракурсами не рекламирует переносимые места.

## Проверки

На Godot4.7.2, native headless input dispatch, с изолированным XDG-профилем:

- `tests/test_stage_targets.gd`: **23 проверки, 0 ошибок**, семь настоящих
  нажатий через `Input.parse_input_event`. Включены occupied-slot priority,
  invalid-place без смены предмета, имя при140%, лодка/линия/груз L02 и
  неизменность state hash.
- `tests/test_stage_input_edges.gd`: **7 проверок, 0 ошибок**, девять событий
  ввода: release-only, canceled release, перемещение за порог и явное размещение.
- `git diff --check`: PASS. Сообщений движка/утечек в этих двух прогонах нет.

Это не физический Android и не тест удобства пальцем. Визуальный проход
полного нового UI и проверка с другими 30уровнями выполняются общей QA.
Новые изображения и художественный стиль в этой правке не вводились.
